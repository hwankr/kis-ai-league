# kis-ai-league

2026 한투모투배틀 AI리그의 대시보드·백엔드·전략·운영 기록을 관리합니다.

기본 브랜치: `main`. Python 3.11+ API·SQLite와 React·TypeScript·Vite 기반 로컬 대시보드입니다. 기본 서버는 외부 Python 패키지가 필요 없고, 타임폴리오 연동은 선택 패키지 Playwright를 사용합니다. 화면 빌드에는 Node.js 24 LTS를 권장합니다.

| 문서 | 내용 |
| --- | --- |
| [AI리그 핵심 규정](docs/competition-rules.md) | 참가 조건, 수상 요건, 거래 제한, 일정, 확인이 필요한 조항 |
| [일봉 추세매매 연구](docs/strategy-hypothesis.md) | 진입·청산 검증, 외부 자료 연결, 재현 방법 |
| [프로젝트 기록](docs/project-log.md) | 결정·실험·운영 결과 |

시간 기준: `Asia/Seoul`. API 키·계좌번호·개인 증빙은 Git에 저장하지 않습니다.

`config.local.toml`에 모의투자 키를 입력합니다. 잔고 조회에는 모의 계좌 앞 8자리와 뒤 2자리도 필요합니다. 새 환경에서는 `config.example.toml`을 복사하고 `python -m venv .venv`로 준비합니다.

```powershell
npm ci
npm run build
.\.venv\Scripts\python.exe -X utf8 -m backend.dashboard
```

`npm ci`는 최초 설치·의존성 변경 시, `npm run build`는 화면 소스 변경 후 실행합니다. Python 서버가 `frontend/dist/`를 제공하므로 평소 실행에는 별도 Node 서버가 필요하지 않습니다.

화면 개발 시 Python 서버를 켜 둔 채 별도 터미널에서 `npm run dev`를 실행하고 [개발 화면](http://127.0.0.1:5173)을 엽니다. `/api`는 기존 8765 서버로 전달됩니다. React 소스는 `frontend/src/`, 로컬 폰트는 `frontend/public/fonts/`에 있습니다.

화면은 [내 계좌](http://127.0.0.1:8765/#/account)·[거래 내역](http://127.0.0.1:8765/#/trades)·[후보 탐색](http://127.0.0.1:8765/#/candidates)·[시세·차트](http://127.0.0.1:8765/#/chart)로 나뉩니다. 메뉴 이동 시 계좌 선택·후보 필터·조회 상태를 유지합니다. 종목 선택은 차트 화면으로 연결되며, 차트 주소에 종목·주기가 저장되어 새로고침과 앞뒤 이동에서도 복원됩니다. 후보 화면 진입은 저장 상태만 확인하며 전체 재계산은 **전체 조회**로 실행합니다.

내 계좌에서 총평가액·예수금·유가평가액·보유 종목의 평가손익을 조회합니다. 30초 자동 갱신과 수동 새로고침을 지원하며, 실패 시 마지막 정상 조회값과 시각을 유지합니다. 평가손익은 대회 수익률이나 실현손익이 아닙니다.

대시보드의 새 조회가 성공하면 조회 시각·총자산·예수금·보유 종목을 `.local/account-history.sqlite3`에 저장합니다. 캐시 응답·조회 실패는 추가하지 않으며, 같은 금액이어도 새 조회는 기록합니다. 선택한 계좌의 최근 2,000건을 자산 변화 그래프로 표시하고 전체 기록은 로컬에 유지합니다. 화면을 닫아도 아래 무인 운영의 계좌 기록은 계속됩니다.

이력은 프로필 ID·키·계좌번호 조합별로 분리됩니다. 키(시크릿 포함)나 계좌번호를 바꾸면 기존 이력과 분리하고, 표시 이름만 바꾸면 이어집니다. 서버 재시작 후에도 이력은 유지되며, DB 파일은 Git과 HTTP 공개 대상에서 제외됩니다.

거래 내역은 기본 최근 30일, 한 번에 최대 90일을 조회합니다(앱 제한, KST). 같은 SQLite와 계좌 분리 기준을 사용하며 주문일·종목·매수/매도·누적 체결수량·평균 체결가를 표시합니다. 전체 페이지 조회 후 주문일·주문채번지점·주문번호별로 갱신하여 반복 조회·부분체결을 중복 합산하지 않습니다. 응답에서 빠진 기존 주문은 보존합니다. 조회·저장 실패는 빈 결과와 구분하고 마지막 저장값을 유지합니다. 잔고와 별도로 수동·30초 자동 갱신합니다.

체결 API 근거: [KIS 공식 조회 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_ccld/inquire_daily_ccld.py)의 모의 TR `VTTC0081R`·`VTSC9215R`, 15건/페이지·연속조회 키를 사용합니다. [3개월 월 경계](https://github.com/koreainvestment/open-trading-api/blob/main/legacy/Sample01/kis_domstk.py)를 넘으면 구간을 나눠 조회합니다. [응답 필드](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_ccld/chk_inquire_daily_ccld.py)는 주문별 누적 집계이며 개별 체결 시각·가격 목록은 제공하지 않습니다.

계좌 추가·전환:

1. [설정 예시](config.example.toml)의 `accounts.competition` 블록을 `config.local.toml` 끝에 추가하고 발급받은 키·계좌번호를 입력합니다. 기존 일반 모의투자 설정은 그대로 사용할 수 있습니다.
2. 대시보드 **새로고침 → 계좌 선택**. 서버 재시작 없이 반영하며, 마지막 선택을 브라우저에 기억합니다. 미완성 계좌는 선택할 수 없습니다.

계좌별 잔고·조회 상태를 분리하며, 전환 중에는 이전 계좌 값을 비웁니다. 모의 서버만 연결하며 자동 주문 설정은 아래 실험실에서 별도로 관리합니다. 대회 계좌의 실제 인증·조회는 발급 후 확인합니다. 포트가 사용 중이면 `--port 8766`을 붙입니다. 종료는 `Ctrl+C`입니다.

시세 수집은 별도 터미널에서 실행합니다. 브라우저·대시보드 서버를 닫아도 수집 프로세스가 켜져 있으면 계속 기록합니다. PC 종료·절전 중에는 수집하지 않으며 자동 시작은 등록하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m backend.collector
# 다른 터미널에서 상태 확인·종료
.\.venv\Scripts\python.exe -X utf8 -m backend.collector --status
.\.venv\Scripts\python.exe -X utf8 -m backend.collector --stop
```

한 번만 수집하려면 `--once`를 붙입니다. 같은 저장소의 중복 실행은 거부하며 종료 요청은 진행 중인 API 요청이 끝난 뒤 완료됩니다. 기본 설정은 005930·60초입니다. [설정 예시](config.example.toml)의 `market_data`에서 종목 1~20개와 주기 10~3600초를 지정합니다. 한 회차를 마친 뒤 지정한 시간만큼 대기하며, 설정 변경은 다음 회차에 반영합니다. `account`를 생략하면 기본 계좌의 키를 사용합니다.

현재가·전일 대비율·누적 거래량·누적 거래대금·조회 시각을 `.local/market-history.sqlite3`에 저장합니다. 시세는 계좌 선택과 무관하게 출처·시장·종목별로 공유하며, 민감한 인증값은 저장하지 않습니다. 성공한 새 조회는 가격이 같아도 기록하고 같은 저장 ID의 재시도는 중복 제외합니다. 실패 시 시세를 추가하지 않고 마지막 값과 오류를 유지합니다. 대시보드의 **시세 수집** 영역은 저장값과 수집기 상태만 읽으며 직접 수집하지 않습니다. 수집기 상태가 20초 넘게 갱신되지 않으면 수집 지연으로 표시합니다.

[KIS 현재가 공식 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_price/inquire_price.py)의 모의 API `FHKST01010100`·KRX를 사용합니다. [거래량·거래대금 필드](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_price/chk_inquire_price.py)는 누적값이므로 조회별로 합산하지 않습니다. 이 API에는 거래일·체결시각이 없어 로컬 조회 시각만 기록합니다. 휴장 중에도 마지막 시세가 반환될 수 있으며, 저장값은 개별 체결이나 분봉이 아닙니다.

종목명은 [KIS 공식 코스피·코스닥 종목 파일](https://github.com/koreainvestment/open-trading-api/tree/main/stocks_info)을 `.local/stock-names.json`에 보관해 표시합니다. 24시간 지난 목록은 화면 조회 시 백그라운드에서 갱신하며 시세 API를 추가 호출하지 않습니다. 갱신 실패 시 이전 이름을 유지하고, 이름이 없는 종목은 코드로 표시합니다.

시세 목록의 종목명을 누르거나 **종목 차트**에 6자리 코드를 입력하면 캔들·거래량을 조회합니다. 일봉·5분봉·15분봉을 선택할 수 있고, 봉을 가리키거나 터치·좌우 방향키로 시가·고가·저가·종가·거래량을 확인합니다. 최초 화면 로딩에서는 차트 API를 호출하지 않으며 차트는 수동으로 갱신합니다.

일봉은 [KIS 기간별 시세](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_itemchartprice/inquire_daily_itemchartprice.py)의 수정주가로 최근 180일 범위 중 최대 100개를 표시합니다. 분봉은 [KIS 당일 분봉](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_time_itemchartprice/inquire_time_itemchartprice.py)을 시간순으로 조회해 실제 반환된 최신 거래일의 5분·15분 OHLC와 거래량으로 집계합니다. 체결 없는 분은 추가하지 않고 15:30 종가 경매는 별도 봉으로 표시합니다. 진행 중인 봉은 표시하며, 휴장 중 이전 거래일이 반환되면 그 날짜를 유지합니다. 과거 날짜를 지정하는 분봉 조회는 아직 지원하지 않습니다.

정상 일봉·원시 분봉 캐시를 `.local/chart-cache/`에 최대 32개 보관해 서버 재시작 후에도 재사용합니다. 장중에는 일봉 60초·분봉 30초 동안 재사용하고, 분봉 갱신은 기존 조회 구간과 겹칠 때까지만 받아 최근 봉을 교체합니다. 새 거래일은 다시 전체 조회합니다. 장외에 확인한 차트는 다음 평일 09시까지 재사용하되 당일 장마감 확정은 16시 이후 조회부터 적용합니다. 처음 보는 종목의 하루 분봉은 약 14회 호출이 필요하고, 이후 짧은 간격의 갱신은 대개 1회입니다.

차트는 기존 60초 시세 저장과 별도로 조회하며 `market_data.account` 또는 기본 계좌의 키를 사용합니다. 같은 키의 요청 간격을 기존 조회·수집기와 공유합니다. `/api/chart?symbol=005930&interval=day`에서 주기는 `day`, `5m`, `15m`만 허용합니다. **차트 새로고침**은 `refresh=1`로 캐시 유효기간과 무관하게 재조회하되 오류 후에는 10초 대기합니다. 종목·주기 전환 시 해당 차트의 화면 캐시가 있으면 먼저 표시하며 갱신하고, 실패하면 이전 값과 오류를 유지합니다.

**후보 종목 비교**는 대회 대상 전체의 일봉과 조회 시점의 거래 상태로 관찰 후보를 추립니다. 수정종가·5/20거래일 수익률·소속 시장 지수 대비 차이(%p)·20일 평균 거래대금·최근 거래대금 배수를 표시하며, [KIS 일별 지수 API](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_indexchartprice/inquire_daily_indexchartprice.py)를 사용합니다. 현재 선정 기준과 검증 결과는 [관찰 후보 선정 근거](docs/candidate-selection.md)를 따릅니다.

대상은 [KRX 지수구성종목](https://data.krx.co.kr/contents/MDC/MDI/mdiLoader/index.cmd?menuId=MDC02010301)에서 받은 기준일 코스피200·코스닥150 목록을 저장한 [고정 종목군](config/competition-universe.json)입니다. 원본 확인·등록 결과는 [프로젝트 기록](docs/project-log.md), 기준일과 거래 제한은 [대회 규정](docs/competition-rules.md)을 따릅니다.

원자료를 확인한 JSON은 `python -m backend.universe import <파일 경로>`로 가져옵니다. 필수 필드는 `status: "verified"`, `as_of`, 시간대가 있는 `checked_at`, `source_kind`, 공식 HTTPS `source_url`, `count`, `rows`입니다. 각 행은 `symbol`(숫자·영문 대문자 6자리 문자열)·`name`·`board`(`KOSPI` 또는 `KOSDAQ`)로 구성합니다. `official_index_constituents`는 두 원본의 `sources` 기록(`board`, `index_name`, `as_of`, `filename`, `row_count`, `sha256`, `source_url`)을 요구하며 목록을 실제 원본 행 수와 대조합니다. 주최측 전체 목록은 `official_competition_list`를 사용합니다. 가져오기는 형식·기준일·중복·개수를 검사하며 원자료의 진위를 자동 인증하지 않습니다. 종목군 포함이 당일 매매 가능 여부를 보장하지는 않습니다.

**전체 조회**를 누르면 종목 수집 설정의 20개 제한과 독립적으로 전체를 순차 조회하고 진행 건수·실패 이유를 표시합니다. 기본 화면은 관찰 후보이며, 관찰 후보·순위 대기·제외·확인 필요(미확정) 필터로 나머지 상태와 이유를 확인합니다. 검색·시장 필터·지표 정렬·25건 페이지와 종목 차트 연결을 지원합니다. 목록 등록 전에는 조회가 비활성이고, 등록 후 **상태 다시 확인**으로 반영합니다. 브라우저를 닫아도 Python 서버가 켜져 있으면 진행하며, 서버 종료로 중단되면 무인 운영에서 재시도합니다. 30초 계좌 화면 갱신은 전체 비교를 실행하지 않습니다.

계산은 KST 16시 전에는 전일까지, 이후에는 당일까지 요청해 두 지수의 최신 거래일과 직전 20거래일을 맞춥니다. 필요한 일봉이 없는 종목·기준일 거래량 0은 제외하고, 잘못된 수치·날짜·조회 실패는 별도로 표시합니다. 수익률은 기준일 종가를 5/20거래일 전 종가와 비교합니다. 평균 거래대금은 기준일 포함 20거래일, 배수는 기준일 거래대금을 **기준일 제외 직전 20거래일 평균**으로 나눈 값입니다. 분모가 0이면 배수는 `—`입니다.

조회 원본·완료 결과는 `.local/candidates/`에 저장합니다. 같은 기준일의 정상 종목 일봉을 재사용하고 지수는 60초 후 재조회합니다. 선별용 지수·종목 과거 이력은 `history/`에 보관하며 최신 응답과 겹친 값이 모두 같을 때만 재사용합니다. 겹침이 없거나 값이 바뀌면 과거 이력을 다시 조회하고, 부족한 거래일을 보간하지 않습니다. 추가 이력 조회가 실패해도 기존 비교 지표를 유지합니다.

화면 열기와 **상태 다시 확인**은 저장값만 읽습니다. 선별·마스터·현재가 상태의 확인 시각 중 하나라도 6시간이 지나거나, 조회 가능한 날짜가 진전되거나, 대상 목록·선정 정책이 바뀌면 이전 결과로 표시하고 **전체 조회**로 갱신합니다. 전체 갱신 실패 시 이전 결과·기준일을 유지합니다. 시세 키는 `market_data.account` 또는 기본 계좌를 사용하고 기존 API 요청 간격을 공유합니다.

**전진 관찰**은 대시보드 서버가 처음 시작할 때 필요한 일봉을 수집하고, 이후 KST 16시부터 새 요청일의 후보·연구 신호를 자동 기록합니다. 브라우저를 닫아도 서버가 실행 중이면 계속하며, 수집 실패·부분 완료는 30분 간격으로 재시도합니다. PC 종료·절전 중에는 기록하지 않습니다. 후보 탐색에서 미채택 상태·신호·가상 결과·오류를 확인합니다. 모의 주문은 아래 실험실이 담당합니다.

관찰 원본은 `.local/forward-observations/<버전 해시>/`에 보존하며 `/api/research`는 상태 조회만 제공합니다. 큰 시장 자료는 내용 해시별로 한 번 압축 저장하고 요청·판정 기록은 따로 남깁니다. 기존 원본은 유지하며 파일이 바뀌지 않으면 검증된 조회 결과를 재사용합니다. 과거 일봉을 새 성과로 세지 않는 기준, 가설·비교 결과·평가 일정은 [전략 연구](docs/strategy-hypothesis.md#전진-관찰)를 따릅니다. 투자금·동시 보유 수는 설정하지 않습니다.

## 실험실

[실험실](http://127.0.0.1:8765/#/experiments)은 **추세 돌파·조정 후 회복·시장 대비 강세·LLM 근거 분석**을 병렬 기록하고 모의계좌에서 실행합니다. 기존 연구의 채택 여부와 별개인 실험이며 실제 계좌 성과와 가상 신호 성과를 구분합니다.

- **분석:** 후보 자료를 자동 갱신하고 완료 일봉의 최대 20종목을 판정합니다. 시작 시 누락분도 처리하며, 실패는 간격을 늘려 재시도합니다. 같은 자료·코드·모델의 성공 결과는 다시 뽑지 않습니다. 입력·코드·모델·프롬프트 해시와 판정 시각을 보존합니다. 목록은 요약을 조회하며 가상 성과는 판정·관련 일봉·달력이 바뀔 때만 다시 계산합니다.
- **Codex:** 설치된 실행기를 [비대화형 모드](https://developers.openai.com/codex/noninteractive/)로 호출하며 기존 [ChatGPT 로그인](https://developers.openai.com/codex/auth/)과 모델 설정을 사용합니다. 별도 API 키는 필요하지 않지만 Codex 사용 한도가 적용됩니다. 데스크톱 채팅에 직접 메시지를 보내는 방식은 아닙니다. 계좌·키를 전달하지 않고 도구 실행을 끈 상태에서 일봉 지표를 분석합니다. 뉴스·공시 자동 수집은 아직 연결하지 않았습니다. 공급자 설정은 [설정 예시](config.example.toml)를 따릅니다.
- **자동 배분:** `[experiments] autonomous = true`이면 기본 모의계좌의 최초 평가액으로 예산을 정하고 자동 시작합니다. 초기 정책은 예산의 1/6을 하루 매수 범위로, 이를 네 전략과 각 전략의 매수 신호 수로 나누며 5거래일 보유합니다. 전체 전략 운용에서는 아래 [자기 개선](#자기-개선)이 검증한 정책으로 교체할 수 있습니다. 계좌·예산·일일/건당 한도는 학습기가 바꾸지 않습니다. 수수료·예약액·기존 보유·현금·매수가능수량과 같은 계좌·날짜·종목의 중복 주문 방지를 적용합니다. 기존 수동 설정은 보존합니다.
- **실행:** 30초마다 체결을 대조합니다. KST 09:05~15:15에 당일 최근 3분 이내 거래가 확인된 종목만 현재가 지정가로 주문합니다. 직전 실제 거래일의 분석이 당일 09시 전에 저장돼 있어야 진입합니다. 보유기간·종가 기준 손절/익절은 매수 당시 정책을 따르며 청산은 다음 거래일에 처리합니다. 기본 보유기간은 진입일 포함 5거래일, 당일 미체결 취소 대기는 10분이며 취소 요청은 16시 전까지 유지합니다. 전일 잔량은 확인 없이 종결하지 않습니다. 수동 보유 종목에는 신규 진입하지 않고 시스템 체결 수량만 매도합니다.
- **복구:** 접수 직전 주문 의도를 저장하고 재시작 후 체결 대조를 거쳐 자동 재개합니다. 일시 오류는 재시도하고 접수 불명은 신규 매수를 격리하며 재전송하지 않습니다. 증권사 주문번호·지점번호가 필요한 경우 질문과 대조 입력을 표시합니다. 취소 응답도 체결 조회로 확인합니다. `신규 주문 정지`는 재시작 후에도 유지되며 기존 미체결을 자동 취소하지 않습니다.
- **비교:** 가상 평균은 신호일별 평균 개별 거래손익이며 계좌 수익률이 아닙니다. 수수료·세금과 편도 슬리피지 0.1%/0.2%를 적용하고, 지연·결측·가격 수정·체결 불확실을 별도로 집계합니다. 같은 종목의 겹친 신호가 포함될 수 있고 여러 버전 합산 여부를 표시합니다. 실제 체결의 실현손익도 규정 비용을 적용한 추정치입니다.

기록은 `.local/experiments/experiments.sqlite3`에 보존합니다. `/api/experiments`의 GET은 조회, POST는 분석·설정·시작·중지·체결 확인·취소·미확정 대조입니다. 주문 전송·취소는 [KIS 현금주문](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/order_cash/order_cash.py)·[취소 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/order_rvsecncl/order_rvsecncl.py)의 모의 TR과 KRX만 사용합니다.

### 자기 개선

전체 전략 운용에서 **후보 연구 → 이후 관측으로 비교 → 자동 채택·퇴역 → 채택 후 비교·복귀**를 반복합니다. `[experiments.learning] enabled`는 생략하면 `experiments.autonomous`를 따릅니다. 주문을 정지한 상태에서도 프로그램이 실행 중이면 연구·가상 비교는 진행하며 주문 권한을 켜지 않습니다.

- **연구:** 완료 자료의 전체 종목군에서 8개 가격·거래량 특징값을 사용합니다. 기존 Codex/호환 LLM의 구조화 제안과 성과 피드백을 반영한 규칙 탐색으로 최대 16개 후보를 비교합니다. 조건·순위·종목 수·전략 구성·비중·현금 유보·보유기간·손절/익절·진입 갭을 바꿀 수 있습니다. 실행할 코드를 생성하거나 기반 모델의 가중치를 훈련하지 않습니다. 확정 주문 5건 이상일 때 실제 거절·체결 비율도 연구에 반영하며 미해결 주문은 실패로 계산하지 않습니다.
- **평가:** 후보 1개를 고정한 뒤 새 관측만 사용해 기존 정책과 같은 초기자금·한도로 비교합니다. 정수주·중복 종목·현금·수수료·세금·슬리피지 0.1%/0.2%를 반영합니다. 기존 과거 연구는 개발에만 재사용하며 당시 종목군·거래 가능 여부가 검증된 미사용 평가 자료로 취급하지 않습니다. 하루 원본은 한 번 저장하고 가격 수정·누락 거래일·장전 미완료 관측·한도/평가 코드 변경은 해당 비교를 다시 시작합니다.
- **교체 기준:** 최소 40거래일 관측·후보 완결 거래 20건. 관측 수에는 첫 진입 신호 기준일을 포함합니다. 기본/높은 비용 수익률이 모두 양수이고 기존보다 각각 1%p 이상 높아야 합니다. 전·후반 수익률도 각각 우세해야 하며 기본 낙폭은 15% 이하이면서 기존보다 2%p 넘게 나빠지면 안 됩니다. 높은 비용 낙폭도 15% 이하여야 합니다. 거래 수 부족은 최대 120거래일까지 기다립니다. 이는 초기 운영 기준이며 수익 보증이나 통계적 유의성 판정이 아닙니다.
- **적용·복귀:** 새 정책으로 장전 분석을 완료한 뒤 신규 진입에 적용합니다. 기존 보유의 청산 규칙은 유지합니다. 채택 이후 최소 20개 새 관측에서 이전 정책과 비교해 낙폭 15% 초과 또는 평가 기간 전·후반 모두 열세·총수익 2%p 초과 열세가 발생하고, 이전 정책의 높은 비용 수익률·낙폭이 더 나으면 복귀합니다. 비중·현금 유보는 설정 예산 기준이며 전략 실현손실을 계좌의 다른 현금으로 보충하지 않습니다.

연구는 별도 작업자로 실행하고 주문 경로에서는 채택된 규칙만 계산합니다. 일봉 평가는 다음 시가 체결 가정이므로 실제 09:05 이후 지정가 체결·미체결과 차이가 있습니다. 분 단위 취소시간은 일봉으로 평가할 수 없어 자동 탐색하지 않습니다. 뉴스·공시 수집과 임의 코드 수정은 이 개선 범위에 포함되지 않습니다. 화면에는 현재/후보 정책·관측 수·비교 성과·마지막 교체만 표시하며, 원본 일별 특징값과 정책·평가 기록은 기존 DB에 보존합니다.

감시자는 8765 서버를 소유하고 종료·응답 지연 시 1~60초 간격으로 재시작합니다. 중복 실행은 거부하며 다른 프로세스를 종료하지 않습니다. 상태·로그는 `.local/supervisor/`, 조회 전용 상태 API는 `/api/health`입니다. API 요청에는 `X-KIS-Dashboard: 1` 헤더가 필요합니다.

브라우저 없이도 후보 수집·Codex 분석·주문·대조·계좌 기록이 이어집니다. 계좌는 평일 08~17시 5분, 그 외 30분 간격으로 기록합니다. 실험실은 최초 자동 관측 대비 계좌 수익률·관측 평가액 기준 최대 낙폭·17시 이후 일별 집계를 표시합니다. 외부 입출금·계좌 초기화는 수익률에 포함되므로 실험 도중 별도 계좌 조작은 기록 확인이 필요합니다. 정상 오류 복구는 자동 처리하며 장기 연결 오류·인증·미확정 주문만 질문으로 남깁니다.

현재 채팅의 아침 08시·저녁 19시 점검은 Codex 앱 자동화에서 관리합니다. 중요한 변화·복구 실패·새 질문만 알립니다. PC 종료·절전 중에는 매매하지 않으며 로그인 후 서버가 자동 재개됩니다. 사용자 주문 정지는 유지됩니다. 실제 체결 전에는 주문·수익 성과를 검증 완료로 표시하지 않습니다.

### 대회 계좌 연결

대회용 키·계좌를 별도 `competition` 프로필로 추가하고, 실험실 **고급 운용 설정**에서 주문 계좌·실행 전략·예산·일일/건당 한도를 함께 저장합니다. 대시보드 조회 계좌 변경만으로 주문 계좌는 바뀌지 않습니다. 기존 전략 보유·미체결이 있으면 설정을 바꿀 수 없습니다.

대회 계좌는 제한된 규모로 주문을 시작해 API 접수·체결·취소·원장 대조를 확인한 뒤 운용을 확대합니다. 장전 분석과 단일 실행 PC의 장중 가동도 확인합니다. 네 전략 분석은 실행 전략 선택과 무관하게 유지됩니다. 한 전략으로 바꿔도 기존 한도 금액은 자동 변경되지 않습니다. 현재 대회 종료일 자동 중지와 [수상조건](docs/competition-rules.md#수상에-필요한-조건)의 누적 집계는 구현되어 있지 않습니다. 전략 채택 상태는 [연구 문서](docs/strategy-hypothesis.md)를 따릅니다.

### 타임폴리오 자동 연동

[별도 실행기](backend/timefolio_mirror.py)는 **이 프로젝트 AI 주문의 확인된 KIS 체결만** 타임폴리오 RFM 13회 대회에 비중 주문으로 반영합니다. 수동·다른 프로그램의 주문은 제외합니다. 공개 주문 API는 확인되지 않아 사이트의 주문 화면과 CSV 내보내기를 사용합니다. 규정·주문 방식은 [대회 문서](docs/competition-rules.md#타임폴리오-제13회-rfm)를 따릅니다.

실행 준비:

1. 이 변경을 읽도록 기존 대시보드를 재시작합니다([감시자 명령](#무인-운영)). 사용자 주문 정지는 유지됩니다.
2. 아래 선택 패키지를 설치합니다. 설치된 Chrome을 사용하므로 별도 Chromium 다운로드는 필요 없습니다.
3. 처음에는 **KIS의 시스템 보유와 타임폴리오 보유·미체결이 0인 상태**로 연동을 시작합니다. 별도 Chrome 창에서 로그인하고 콘솔의 Enter를 누릅니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-mirror.txt
.\.venv\Scripts\python.exe -X utf8 -m backend.timefolio_mirror run
```

이후에는 [start-timefolio-mirror.cmd](start-timefolio-mirror.cmd)로 실행할 수 있습니다. `status`는 저장된 상태만 조회하고, `login`은 로그인만 준비합니다. 인자 없이 실행해도 `status`입니다. 기존 대시보드·로그인 자동 시작에 연동 실행기를 등록하지 않습니다. KIS 신규 주문 정지가 켜져 있으면 타임폴리오 새 주문도 나가지 않으며, 이 프로그램은 KIS 주문을 켜지 않습니다. 종료는 Ctrl+C입니다. 이미 접수된 주문은 자동 취소하지 않습니다.

- 최초 시작 전 과거 체결은 재생하지 않습니다. 새 체결이 생긴 종목만 `AI 보유수량 × 잔고 현재가 ÷ KIS 계좌 평가액`을 목표 비중으로 계산하고, 타임폴리오 보유·미체결을 차감해 0.01%p 단위로 주문합니다. 한 회차에 잔고를 한 번 평가하며, 주문 작성 중 가격 변화로 다시 계산하지 않습니다. 상대호가 5·즉시 실행, 거래일 09:00~15:19에 제출합니다.
- 기본 30초 간격으로 체결을 읽습니다. 타임폴리오 적용 단계는 종목 적격성·거래량·현금·섹터 한도를 재심사하지 않고 사이트의 실제 접수·거절 결과를 따릅니다. 제출 직전에는 계좌·중지 상태·새 체결과 작성된 주문값을 확인합니다. 같은 종목의 진행 중·접수 불명·수동 주문은 그 종목만 보류합니다.
- 기존 `.local/experiments/experiments.sqlite3`에 관측 커서·제출 의도·접수 결과를 저장하고, 변화 없는 결과는 다시 쓰지 않습니다. 접수 불명은 재클릭하지 않습니다. 확정 거절·취소·부분 처리 종료의 부족분은 다음 새 AI 체결 때 계산하며, 0.01%p 미만 차이는 종료합니다. `completed`는 사이트의 처리 종료이며 전량 체결을 뜻하지 않습니다.
- 로그인은 `.local/timefolio-browser/`의 전용 Chrome 프로필에 유지합니다. 화면·CSV·반복 로그를 별도 누적하지 않습니다. 연동 중 같은 타임폴리오 계정을 직접 주문하거나 화면 필터를 바꾸지 않습니다.

현재 검증은 오프라인 테스트와 사이트 화면·공개 프런트 코드 대조까지입니다. **실제 자동 제출·체결은 실행하지 않았습니다.** 자본금·비용·체결 방식이 달라 KIS와 체결가·수익률이 같아지지는 않습니다.

체결 원천 `GET /api/mirror?after=0&limit=100`은 `X-KIS-Dashboard: 1` 헤더가 필요한 읽기 전용 API입니다. 최대 200건씩 `has_more=false`까지 읽고 마지막 응답의 전체 시스템 보유를 사용합니다. 관측 커서는 목적지 주문 완료와 별개이며, 원장과 체결 증분은 같은 DB 트랜잭션으로 저장합니다.

CLI:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m backend.kis check
.\.venv\Scripts\python.exe -X utf8 -m backend.kis auth
.\.venv\Scripts\python.exe -X utf8 -m backend.kis quote 005930
.\.venv\Scripts\python.exe -X utf8 -m backend.kis balance
.\.venv\Scripts\python.exe -X utf8 -m backend.kis --account competition balance
```

`check`는 로컬 설정만 확인합니다. 인증 토큰은 키별로 `.local/`에 분리해 저장·재사용합니다. API 기준: [KIS 공식 예제](https://github.com/koreainvestment/open-trading-api).

검증: `npm test`(프런트 회귀 테스트), `npm run build`(타입 검사·빌드), `.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests`(Python 오프라인 테스트).
